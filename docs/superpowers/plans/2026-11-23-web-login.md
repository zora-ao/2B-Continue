# Web Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users register, log in and log out on the web app, and keep every API call working behind the #18 login.

**Architecture:** `api.js` handles the CSRF header and a single silent refresh. An `AuthProvider` holds the current user. A `RequireAuth` layout route guards the app pages, and the public auth pages share an `AuthCard`.

**Tech Stack:** React 19, react-router-dom 7, Tailwind v4, shadcn/ui, plain JavaScript.

**Spec:** `docs/superpowers/specs/2026-11-23-web-login-design.md`

## Global Constraints

- **Project rules (`CLAUDE.md`):** plain JavaScript, no tests, no React Query. Verify each task with `npm run build` and a browser check.
- **Test against the throwaway backend only:** port 5001, never the real backend on port 5000. Test credentials live only in the uncommitted scratchpad script and are never typed into chat.
- **Tokens stay in cookies:** never read or store tokens in JS. Only the `csrf_access_token` and `csrf_refresh_token` cookies may be read.
- **Modern Web Guidance:** follow `autofill-sign-in-form`, `autofill-sign-up-form` and `forms`, and add the disclosure section to the PR.
- **Branch:** `feat/frontend/web-login`. It is cut from `feat/frontend/appliance-scan`, because #19 changes the same `App.jsx`, `api.js` and `Sidebar.jsx`. If #19 is merged first, branch from `main` instead.
- **No AI attribution** in commits or the PR.

## Review Focus

1. **Several requests get 401 at once** (the dashboard loads 2–3 calls). Exactly one refresh runs, and every request retries once.
2. **The refresh itself fails** (an expired refresh cookie). The app must not loop: `auth:expired` fires once, and the user lands on `/login` with `from` kept.
3. **Auth endpoints return 401** (a wrong password). This must not trigger a refresh or `auth:expired`, only the form error.
4. **Opening an app page while logged out.** No dashboard flash appears; a spinner shows until `me()` answers.
5. **The phone page `/scan/:code`** stays reachable without a login.

### Task 1: Auth calls, CSRF and refresh in `api.js`

**Files:** Modify `frontend/src/api.js`.

**Interfaces (produces):**
- `api.me() → Promise<{id, name, email}>`
- `api.login({email, password}) → user`
- `api.register({name, email, password}) → user`
- `api.logout() → null`
- The `"auth:expired"` window event.

- [ ] **Step 1: Add `readCookie(name)`.** On methods other than GET and HEAD, add `X-CSRF-TOKEN` (from `csrf_access_token`) to the headers in `request()`.
- [ ] **Step 2: Retry after one refresh.**
  - When the response is 401 and the path doesn't start with `/auth/`, run the shared `refreshLogin()` promise. It posts to `/auth/refresh` with `X-CSRF-TOKEN` from `csrf_refresh_token`; a 409 counts as success. Then retry the original request once, with a fresh CSRF header.
  - If the refresh fails, call `window.dispatchEvent(new Event("auth:expired"))` and throw the 401 error.
- [ ] **Step 3: Add the four auth methods.** `me`, `login` and `register` unwrap `data.user`.
- [ ] **Step 4: Run `npm run build`.** Expected: it passes.
- [ ] **Step 5: Commit** with the message `feat(frontend): send login CSRF header and refresh expired logins`.

- [ ] **Step 3: Restructure `App.jsx` routes.**
